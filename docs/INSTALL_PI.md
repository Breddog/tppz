# Прошивка Raspberry Pi і підключення до застосунку

Готові файли — на сторінці **Releases** репозиторію, реліз `pi-N` (найновіший):

| Файл | Що це |
|---|---|
| `sdrwatch-pi-image.img.xz` | **Готова прошивка** — образ SD-карти: Raspberry Pi OS Lite 64-bit + SDR Watch, усе налаштовано |
| `sdrwatch-pi.tar.gz` | Інсталятор для вже встановленої Raspberry Pi OS 64-bit |

Підтримуються **Raspberry Pi 5, 4, 400** (64-bit). Pi 3 — працюватиме, але повільно.

---

## 1. Що потрібно

- Raspberry Pi 5 (рекомендовано) або Pi 4, **офіційний блок живлення** (Pi 5 — 27 Вт, 5.1 В / 5 А; Pi 4 — 15 Вт).
- microSD-карта **16 ГБ+** (A1/A2) або NVMe SSD (краще для кільцевого запису).
- SDR-приймач: **HackRF One** (рекомендовано) або RTL-SDR / Airspy / bladeRF / LimeSDR / PlutoSDR.
- Антена під діапазон (див. `docs/HARDWARE.md`), кабель USB для SDR.
- Мережа: кабель Ethernet до роутера **або** Wi-Fi.

## 2. Підключення заліза

```
  [Антена]──SMA──[HackRF One]──USB (порт USB 2.0, чорний)──[Raspberry Pi]──Ethernet──[Роутер]
                                                                  │
                                                       [Блок живлення USB-C]
```

1. **Антену** — у роз'єм `ANTENNA` HackRF (SMA). Не вмикайте HackRF без антени чи навантаження.
2. **HackRF → Raspberry Pi** коротким кабелем у **чорний порт USB 2.0** (сині USB 3.0 шумлять у районі 2.4 ГГц). Додатковий хаб не потрібен: HackRF споживає ~0.5 А, Pi 5 з офіційним БЖ це тягне.
3. **Мережа:** кабель Ethernet до роутера (найнадійніше) або Wi-Fi (налаштовується у файлі, див. крок 3).
4. **Живлення** підключайте останнім.
5. Якщо є фронтенд із комутатором (docs/HARDWARE.md): керуючі лінії — GPIO17 (пін 11) і GPIO27 (пін 13), земля — пін 6.

## 3. Запис прошивки (варіант А — готовий образ)

1. Завантажте `sdrwatch-pi-image.img.xz` з Releases.
2. Запишіть його на карту програмою **Raspberry Pi Imager** («Choose OS» → «Use custom» → вибрати файл) або **balenaEtcher**.
   *У Raspberry Pi Imager на питання про OS customisation відповідайте «No» — налаштування робляться файлом нижче.*
3. Після запису витягніть і знову вставте карту в комп'ютер. З'явиться диск **`bootfs`**. Відкрийте на ньому файл **`sdrwatch.txt`** у будь-якому текстовому редакторі:
   ```
   NAME=Пост-1
   WIFI_SSID=НазваВашоїМережі        # порожньо, якщо Ethernet
   WIFI_PASSWORD=ПарольWiFi
   WIFI_COUNTRY=UA
   TIMEZONE=Europe/Kyiv
   QUOTA_MB=4096                      # місце під кільцевий запис
   SSH_PASSWORD=                      # задайте, якщо потрібен SSH (користувач sdr)
   HOTSPOT_SSID=sdrdetect             # точка доступу телефону — резервна мережа (див. 4б)
   HOTSPOT_PASSWORD=12345678
   DISABLE_PI_WIFI=0                  # 1 — вимкнути Wi-Fi/BT Pi (тільки при Ethernet; резерв через телефон тоді не працює)
   ```
   Збережіть, безпечно вийміть карту.
4. Вставте карту в Raspberry Pi, увімкніть живлення. Перший запуск триває **2–3 хвилини** (розширення файлової системи, налаштування). Після цього файл стане `sdrwatch.applied.txt`, а паролі в ньому затруться.

## 3б. Варіант Б — на вже встановлену Raspberry Pi OS

Запишіть звичайну **Raspberry Pi OS Lite (64-bit)** через Raspberry Pi Imager (у налаштуваннях задайте Wi-Fi, увімкніть SSH), зайдіть по SSH і виконайте:
```bash
curl -LO https://github.com/Breddog/tppz/releases/download/pi-N/sdrwatch-pi.tar.gz   # N — номер релізу
tar xzf sdrwatch-pi.tar.gz
sudo ./sdrwatch-pi/install.sh
```
Наприкінці інсталятор покаже QR-код для застосунку й адресу сторінки модуля.

## 4. Сполучення з застосунком

Встановіть застосунок (APK з релізу `apk-N`). Телефон має бути **в тій самій мережі**, що й модуль.

**Найпростіше — протягом 15 хвилин після ввімкнення модуля:**
1. Застосунок → **«Додати модуль»** → **«Знайти в локальній мережі»**.
2. Натисніть на знайдений модуль із зеленим «+» — він додасться сам, без паролів.

**Або через QR-код:**
- відкрийте в браузері (на телефоні чи комп'ютері) **`http://sdrwatch.local:8080`** або `http://<IP-модуля>:8080` — у перші 15 хвилин там показано QR-код; у застосунку — «Сканувати QR-код модуля»;
- або по SSH: `sdrwatch pair` — QR-код у терміналі (працює завжди).

> 15-хвилинне вікно — захист: сторонній у вашій мережі не зможе підключитися пізніше. Щоб додати ще
> один телефон — вимкніть і ввімкніть живлення модуля й додайте його протягом 15 хвилин.

IP-адресу модуля видно в роутері (список клієнтів, ім'я `sdrwatch`).

## 4б. Без інтернету й без спільної мережі — точка доступу телефону

У полі, без роутера чи інтернету, модуль підключається **до точки доступу вашого телефону**:

1. На телефоні увімкніть точку доступу (Налаштування → Точка доступу / Режим модема):
   - **назва мережі: `sdrdetect`**
   - **пароль: `12345678`** (WPA2)
   На iPhone назва точки доступу — це ім'я телефону: Параметри → Загальні → Про пристрій → Назва → `sdrdetect`.
   Мобільний інтернет на телефоні **не потрібен**.
2. Увімкніть модуль (або залиште працювати). Протягом **~1 хвилини** він сам знайде `sdrdetect` і підключиться.
3. Відкрийте застосунок — модуль сам повідомить телефону свою нову адресу, і зв'язок відновиться.
   Новий модуль у перші 15 хв після ввімкнення можна додати: «Додати модуль» → «Знайти в локальній мережі».

Коли модуль переходить на точку доступу (служба `sdrwatch-netwatch`):
- є поруч мережа `sdrdetect`, **і** при цьому
- немає інтернету **або** застосунок не підключався до модуля довше 3 хвилин (тобто телефон не в одній мережі з модулем).

Ethernet-кабель при цьому не відключається. Коли точку доступу вимкнути, модуль повернеться у свою звичайну Wi-Fi мережу.
Назву й пароль можна змінити в `sdrwatch.txt` (`HOTSPOT_SSID`, `HOTSPOT_PASSWORD`).

> Пароль `12345678` загальновідомий: будь-хто може створити точку доступу `sdrdetect`, і модуль до неї приєднається.
> Керувати модулем без токена все одно не вийде (крім перших 15 хвилин після ввімкнення), але для бойового
> використання задайте власний пароль у `sdrwatch.txt` і на телефоні.

## 5. Доступ з інтернету (з будь-якого місця)

Рекомендовано **Tailscale** (безкоштовний VPN, нічого не треба відкривати на роутері):
1. На модулі (через SSH): `curl -fsSL https://tailscale.com/install.sh | sh && sudo tailscale up` — відкрийте показане посилання й увійдіть.
2. Встановіть Tailscale на телефон, увійдіть тим самим акаунтом.
3. Дізнайтесь адресу модуля: `tailscale ip -4` (напр. `100.101.102.103`).
4. У застосунку: модуль → «Керування» → «Адреси та токен» → додайте другий рядок `http://100.101.102.103:8080`.
   Застосунок сам обиратиме локальну адресу вдома й Tailscale — поза домом.

Не відкривайте порт 8080 на роутері напряму в інтернет.

## 5б. Оновлення з застосунку (локально або віддалено)

Модуль → «Керування» → **«Оновлення»** → «Перевірити оновлення»:

- **ПЗ модуля** (реліз `pi-N`) — нова версія SDR Watch; налаштування й історія зберігаються.
- **Прошивка HackRF** (реліз `hackrf-N`) — редакція SDR Watch «лише приймання» на основі офіційної прошивки
  (див. `hackrf/README.md`). Під час запису (~1 хв) не вимикайте живлення.

Телефон сам завантажує файл з GitHub і передає модулю — модулю інтернет **не потрібен**, оновлення працює
і через точку доступу `sdrdetect`, і віддалено через Tailscale. Якщо інтернету немає в телефона, модуль спробує
завантажити оновлення сам. Цілісність перевіряється за SHA-256, встановлює окрема служба `sdrwatch-update` (root),
журнал видно в застосунку.

> Модулі, записані з образу `pi-4` і старіших, ще не мають цієї функції: один раз оновіть їх вручну
> (`sudo ./sdrwatch-pi/install.sh` з новим `sdrwatch-pi.tar.gz`) або перезапишіть образ. Далі — лише з застосунку.

Оновлювати модуль може будь-хто з токеном доступу — бережіть його (і QR-код) так само, як пароль.

## 5в. Тестовий передавач (перевірка приймачів)

Модуль з **HackRF** може сам передати тестовий сигнал, щоб перевірити, чи приймає його інший пристрій
(приймач FPV, сканер, інший модуль) на потрібній частоті. Застосунок: модуль → «Керування» →
«Тестовий передавач».

Режими: чиста несуча, несуча з тоном, тестова таблиця PAL/NTSC, **завантажена картинка як FPV-відео**, шум.
Задаєте частоту, підсилення (починайте з малого) і тривалість — передавач **сам вимикається** за таймером
(макс. 5 хв за замовчуванням). Сканування на час передачі зупиняється (HackRF напівдуплексний).

> **Відповідальність.** Передавайте лише на навантаження (dummy load) чи екрановано, або на частотах і
> потужностях, які вам дозволені. Передача у відкритий ефір регулюється законом і може створити завади.
> Повністю вимкнути передавач на модулі: у `config.json` встановіть `"tx": {"allow": false}` і перезапустіть сервіс.

## 6. Перевірка й типові проблеми

| Симптом | Що зробити |
|---|---|
| Немає роутера / інтернету | Увімкніть на телефоні точку доступу `sdrdetect` / `12345678` (розділ 4б) |
| Застосунок не знаходить модуль | Телефон і Pi в одній мережі? Гостьова мережа роутера блокує пристрої між собою — використайте основну. Спробуйте `http://sdrwatch.local:8080` у браузері |
| «Вікно сполучення закрите» | Вимкніть і ввімкніть живлення Pi, додайте модуль протягом 15 хв |
| Модуль онлайн, але спектр порожній | SDR не видно: `SoapySDRUtil --find` (має показати hackrf). Перепідключіть USB, перевірте живлення |
| Помилки SDR у «Керуванні» | Слабкий БЖ — візьміть офіційний; HackRF у порт USB 2.0 |
| Дуже багато сигналів / все «червоне» | Перевантаження: увімкніть «Автоматичне підсилення», зменшіть LNA, вимкніть AMP |
| Pi гріється > 80 °C | Активний кулер, корпус з вентиляцією |

Корисні команди (SSH, користувач `sdr`):
```bash
journalctl -u sdrwatch -f          # журнал сервісу
sudo systemctl restart sdrwatch    # перезапуск
sdrwatch pair                      # QR-код для застосунку
sudo nano /etc/sdrwatch/config.json && sudo systemctl restart sdrwatch   # ручні налаштування
```

Оновлення ПЗ модуля: завантажте новий `sdrwatch-pi.tar.gz` і виконайте `sudo ./sdrwatch-pi/install.sh` — налаштування й історія зберігаються.
