# SDR Watch — виявлення FPV-дронів: Raspberry Pi + SDR + застосунок для телефону

Система з двох частин:

| Частина | Тека | Що робить |
|---|---|---|
| **Модуль** (Raspberry Pi 4/5 + HackRF One або інший SDR) | [`pi/`](pi) | Сканує ефір, прибирає шум, виявляє й класифікує сигнали, декодує аналогове відео, оцінює відстань, веде кільцевий запис на флешку, надсилає сповіщення, дає API для телефону |
| **Застосунок** (Android / iOS, Flutter) | [`mobile/`](mobile) | Додавання кількох модулів «як камер», живий спектр / водоспад із підказками, живе відео, історія з флешки модуля, дистанційне керування, фонові сповіщення |

> Модуль **тільки приймає**: нічого не передає й не глушить. Перевірте місцеве законодавство щодо
> радіоконтролю та перехоплення радіосигналів.

```
 ┌──────────── Raspberry Pi ────────────┐            ┌──────── Телефон ────────┐
 │ HackRF ─► SoapySDR ─► Сканер ─► DSP  │  HTTP/WS   │ Модулі (сітка «камер»)  │
 │   спектр → шум → детектор → трекер   │◄──────────►│ Ефір: спектр/водоспад   │
 │   класифікатор → відео-декодер → AFC │ LAN / VPN  │ Сигнали / Відео         │
 │   кільцевий запис (SQLite + файли)   │            │ Історія / Керування     │
 │   ntfy / Telegram / вебхук ──────────┼──push────► │ Фонові сповіщення       │
 └──────────────────────────────────────┘            └─────────────────────────┘
```

## Можливості

**Обробка сигналу на модулі (`pi/sdrwatch`)**
- **Виявлення на всій ширині SDR** (HackRF: 1 МГц – 6 ГГц; до 8 ГГц — через конвертер): пріоритетні FPV-діапазони 5.8 ГГц, 1.2–1.3 ГГц, 2.4 ГГц, 868/915 МГц скануються кожен цикл, решта ефіру — порціями між ними; нові сигнали одразу підтверджуються повторними замірами, а FM/ТБ/GSM/LTE/GNSS позначаються як «відома служба» без сповіщень.
- Керування зовнішнім ВЧ-трактом: комутатор антен/фільтрів через GPIO, живлення LNA (bias-tee), понижувальний конвертер — див. [`docs/HARDWARE.md`](docs/HARDWARE.md).
- **Без «порожніх» спрацювань на шумі**: PSD Велча з усередненням, прибирання DC-піку HackRF і країв смуги, оцінка рівня шуму для кожного біна (ковзний перцентиль + довготривалий трекер «швидко вниз / повільно вгору» + глобальний опорний рівень, щоб широкі сигнали DJI не «з'їдали» поріг), морфологічна обробка маски, підтвердження сигналу кількома проходами.
- **Класифікація** навіть тоді, коли відео показати неможливо:
  аналогове відео PAL/NTSC · **інвертоване** відео (виправляється автоматично) · **кодоване/скрембльоване** (cut&rotate, інверсія рядків — зі спробою дескремблювання) · слабке аналогове · **цифрове відео** (DJI O3/O4, Walksnail 10/20/40 МГц, HDZero) · **канали керування** ELRS 2.4/900, Crossfire, FrSky, TBS Tracer (за стрибками частоти FHSS) · телеметрія · Wi-Fi · невідомі.
- **Декодер аналогового відео**: FM-дискримінатор → автовизначення стандарту за періодом рядків → автополярність → «маховик» рядкової синхронізації (добудовує зашумлені імпульси) → кадрова синхронізація → авто-рівні за синхроімпульсом і задньою площадкою → автоконтраст.
- **AFC (автопідстроювання)**: у режимі стеження несуча тримається по центру, навіть коли VTX «пливе».
- **Відомі сітки каналів**: A, B, E, F, R (Raceband), L, U, O, H, 1.2/1.3 ГГц, 3.3 ГГц, DJI/Walksnail, Wi-Fi. Знайдена частота співставляється з каналом («R4, +0.9 МГц»).
- **Ехо-фільтр сталих шумів**: при вмиканні модуль вивчає постійний фон (власні завади, спури Pi/USB, стаціонарні передавачі) і далі не реагує на нього — лишаються тільки нові сигнали.
- **При втраті сигналу** спершу скануються канали тієї ж сітки, потім сусідні — пілот часто просто перемикає канал.
- **Відстань**: логарифмічна модель загасання від RSSI, частоти й типової потужності передавача цього класу → «мін / ймовірна / макс», фільтр Калмана, тренд «наближається / віддаляється», калібрування відомим передавачем, вибір типу місцевості.
- **Кільцевий запис на флешку, як у відеореєстраторі**: виділяєте N ГБ — найстаріші кліпи, кадри й архів водоспаду перезаписуються, журнал подій лишається.
- **Звук з ефіру**: ЧМ вузька (рації, голос), ЧМ широка (FM-мовлення), АМ (авіація) — модуль демодулює, телефон програє; шумодав, автоскан діапазонів (PMR446, LPD433, 2 м, 70 см, морський, авіа, FM).
- **Автоскан відео**: перебір каналів сіток із зупинкою на картинці.
- **Веб-інтерфейс модуля** (http://<pi>:8080): стан, QR для сполучення, перегляд мережі (IP, інтерфейси, Wi-Fi) і налаштування Wi-Fi (додати/забути мережу) прямо з браузера.
- **Багатокористувацький режим / «тільки один»**: кілька телефонів моніторять одночасно; за потреби — лише один керує (решта дивляться), з перехопленням керування.
- **Сповіщення з модуля**: ntfy, Telegram, вебхук (працюють навіть коли телефон «приспав» застосунок).
- **Тестовий передавач** (HackRF): щоб перевірити приймання інших пристроїв на заданій частоті, модуль може **передати** тестовий сигнал — несучу, тон, тестову таблицю PAL/NTSC, завантажену картинку як FPV-відео або шум. Вмикається лише вручну, із авто-стопом за таймером. Передавайте тільки на навантаження/екрановано або на дозволених вам частотах.

**Застосунок (`mobile/`)**
- Кілька модулів на головному екрані як камери спостереження: статус, найнебезпечніші сигнали, останній кадр.
- Додавання: **QR-код** (`sdrwatch pair`), пошук у локальній мережі, вручну. Кілька адрес на модуль (LAN, Tailscale, домен) — застосунок сам обирає доступну.
- **Ефір**: живий спектр із **рівнем шуму та порогом виявлення**, утримання піків, кольорові маркери сигналів із назвою каналу; перемикання на **водоспад** або обидва разом; знизу — **підказки простими словами** про найактивніші сигнали й піки.
- **Сигнали**: список із класом, каналом, RSSI, відстанню; деталі з графіком RSSI, шкалою відстані, параметрами відео й IQ-ознаками.
- **Відео (завжди живе)**: екран показує реальний растр у реальному часі — відео за наявності сигналу або справжній «сніг», коли сигналу немає (ніколи не чорний/синій екран); повзунок по всьому діапазону SDR і ввід частоти, OSD (канал, стандарт, SNR, інверсія, скремблювання), ±0.5/±5 МГц, вибір каналу з сітки, полярність авто/норм/інв, AFC, автоконтраст, дескремблювання, запис.
- **Історія**: події з флешки модуля, фільтри, кадри та **програвач кліпів**, **архів водоспаду** за 10 хв … 7 днів, заповненість флешки.
- **Керування**: режим, діапазони, підсилення LNA/VGA/AMP та авто, поріг, підтвердження, місцевість і калібрування відстані, квота запису, push із модуля, назва/координати, перезапуск, **оновлення ПЗ модуля та прошивки HackRF** (у т.ч. віддалено), **тестовий передавач**.
- **Фоновий режим**: Android — foreground service опитує всі модулі й показує сповіщення (у т.ч. «модуль не на зв'язку»); iOS — background fetch + рекомендовано ntfy/Telegram.

## Обладнання

Повні технічні умови, вибір SDR, антени, підсилювачі, фільтри, схема зібраного пристрою і специфікація — **[`docs/HARDWARE.md`](docs/HARDWARE.md)**. Коротко:

- Raspberry Pi **5** (рекомендовано) або Pi 4 (4 ГБ+), активне охолодження, якісне живлення 5 В / 5 А (HackRF споживає до 0.5 А).
- **HackRF One** (1 МГц–6 ГГц, 20 МГц смуги) — покриває всі FPV-діапазони. Також працюють через SoapySDR: RTL-SDR (лише до 1.7 ГГц і 2.4 МГц смуги — 900 МГц/1.2 ГГц), Airspy, LimeSDR, PlutoSDR, USRP.
- Антени під діапазони (5.8 ГГц патч/гелікс для дальності, всенаправлена для огляду), бажано LNA для 5.8 ГГц.
- microSD/SSD під кільцевий запис.

## Швидкий старт

> **Готові файли:** застосунок для Android — реліз `apk-N`, прошивка Raspberry Pi (образ SD-карти та інсталятор) — реліз `pi-N`, прошивка HackRF «лише приймання» — реліз `hackrf-N` ([`hackrf/README.md`](hackrf/README.md)) на сторінці Releases. Оновлення обох — з застосунку, у т.ч. віддалено. Покрокова інструкція з підключення й сполучення з телефоном — **[`docs/INSTALL_PI.md`](docs/INSTALL_PI.md)**.

### 1. Модуль на Raspberry Pi

```bash
git clone <цей репозиторій> && cd tppz/pi
sudo ./install.sh          # SoapySDR + драйвери, venv, systemd-сервіс, udev
sudo -u sdrwatch SDRWATCH_CONFIG=/etc/sdrwatch/config.json /opt/sdrwatch/venv/bin/python -m sdrwatch pair
```
Остання команда показує **QR-код** з адресою та токеном. Конфіг: `/etc/sdrwatch/config.json` (приклад — [`pi/config.example.json`](pi/config.example.json)); більшість параметрів змінюються з телефону.

Без SDR (демо/розробка) — симулятор ефіру з аналоговим, інвертованим, кодованим, DJI-подібним відео, ELRS та Wi-Fi:
```bash
cd pi && pip install -r requirements.txt
SDRWATCH_CONFIG=./config.json python -m sdrwatch run --sim --storage ./data --port 8080
```

### 2. Доступ з інтернету
Найпростіше й безпечно — **Tailscale** / WireGuard на Pi і телефоні: додайте в модуль другу адресу `http://100.x.y.z:8080`
(`sdrwatch pair --host 100.x.y.z`). Можна також reverse-proxy з HTTPS (Caddy/nginx). Не відкривайте порт 8080 напряму в інтернет без TLS.

### 3. Застосунок
```bash
cd mobile
flutter pub get
flutter build apk --release        # Android: build/app/outputs/flutter-apk/app-release.apk
flutter build ipa                  # iOS (потрібен Mac + Xcode і акаунт розробника)
```
Відкрийте застосунок → «Додати модуль» → відскануйте QR. Для стабільних фонових сповіщень на Android вимкніть для застосунку оптимізацію батареї.

## Як це працює (коротко)

1. **Сканування.** Діапазон ділиться на сегменти по ~16 МГц (80 % від 20 МГц смуги HackRF), на кожному — FFT 1024 з усередненням.
2. **Шум і детекція.** Поріг — «шум + 8 дБ» (≈4σ після усереднення); мінімальна ширина, склеювання розривів, приєднання «супутникових» ліній FM-відео, склеювання сигналів на межі сегментів.
3. **Трекер.** Кандидат стає сигналом після 3 проходів; FHSS-стрибки в діапазонах ELRS/Crossfire збираються в один «лінк керування»; втрата — через 6 с, після чого — пошук по сітці.
4. **Аналіз.** Для нових сигналів знімається 45 мс IQ: огинаюча (FM/LoRa — постійна, OFDM — релеївська), шпаруватість, спроба відео-синхронізації.
5. **RSSI** — повна потужність у смузі сигналу (з поправкою ENBW вікна), переведена в дБм з урахуванням підсилення та калібрування.

Повний опис API — [`docs/API.md`](docs/API.md).

## Обмеження

- Цифрові відеолінки (DJI, Walksnail, HDZero) зашифровані/закодовані — їх **лише класифікуємо**, зображення недоступне.
- Відстань — орієнтир (похибка в рази через відбиття, антени, невідому потужність). Калібрування помітно покращує точність.
- Python-обробка на Pi дає ~2–5 кадр/с живого відео та прохід 5.8 ГГц діапазону за ~0.5–1 с (залежить від моделі Pi).
- HackRF має 8-бітний АЦП: поруч із потужним передавачем вмикайте автопідсилення.
